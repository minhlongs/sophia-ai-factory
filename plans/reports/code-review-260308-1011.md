## High Priority Findings

### 2. In-Memory Rate Limiting [MEDIUM]

**Issue:** Rate limiter uses in-memory Map which is not distributed across Vercel instances.

**Location:** `src/middleware/rate-limiter.ts` lines 36-41

```typescript
private cache = new Map<string, CacheEntry>()
```

**Impact:** Users can bypass rate limits by hitting different Vercel instances.

**Recommendation:** Use Redis/Upstash for distributed rate limiting in production:
```typescript
import { Redis } from '@upstash/redis'
const redis = new Redis({ url: ..., token: ... })

async function checkLimit(key: string, config: RateLimitConfig) {
  const current = await redis.incr(key)
  await redis.expire(key, config.intervalMs / 1000)
  return current <= config.maxRequests
}
```

### 4. Secret Exposure Risk in Client Schema [LOW]

**Issue:** `integrationSchema` allows API secrets to be passed from client.

**Location:** `src/lib/schemas.ts` line 38-42

export const integrationSchema = z.object({
  network: z.enum(["clickbank", "shareasale", "amazon"]),
  api_key: z.string().min(1, "API Key is required"),

**Risk:** Users could potentially submit other users' secrets if not properly validated against their own credentials.

**Recommendation:** Ensure server-side validation that the user owns the integration before storing secrets.
