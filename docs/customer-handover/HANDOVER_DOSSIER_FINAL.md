## 3. Credentials Topology & 1Password Vault Taxonomy / Cấu Trúc Khóa Bảo Mật & 53 Production Secrets

Sophia AI Factory enforces strict zero-trust credential hygiene:
1. **Zero Plaintext Exposure:** Secrets are never written to source control, pull requests, log streams, or markdown files.
2. **Envelope Encryption:** Customer BYOK keys are encrypted at rest with AES-256-GCM using unique initialization vectors (IVs) and tenant-bound authentication data (AAD).
3. **Structured Password Vault:** All 53 Cloudflare Worker secrets and upstream vendor master credentials are deposited into a shared 1Password/Bitwarden vault.

## 5. Customer Operational Governance Charter / Hiến Chương Quản Trị Vận Hành Khách Hàng

The Customer Operational Governance Charter enshrines **5 non-negotiable sovereignty principles** that guarantee customer autonomy and data integrity.

### 5.1 The 5 Sovereignty Principles / 5 Nguyên Tắc Chủ Quyền Khách Hàng

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                   5 SOVEREIGNTY PRINCIPLES OF SOPHIA AI FACTORY                  │
├─────┬─────────────────────────────────┬──────────────────────────────────────────┤
│ #   │ Principle / Nguyên Tắc          │ Operational Enforcement / Biện Pháp Thực │
├─────┼─────────────────────────────────┼──────────────────────────────────────────┤
│ P01 │ Zero Technical Burden           │ 100% Browser UI; 0 CLI, 0 SQL, 0 server  │
│ P02 │ Self-Service Data Portability   │ 1-Click ZIP export; zero vendor lock-in  │
│ P03 │ Zero Model Training & Secrecy   │ AES-256-GCM encryption; zero AI training │
│ P04 │ Strict Multi-Tenant Segregation │ Double-layer IDOR checks; scoped queries │
│ P05 │ Financial Sovereignty & Invariant│ Atomic payment locks; conditional credits│
└─────┴─────────────────────────────────┴──────────────────────────────────────────┘
```

#### Principle 1: Zero Technical Burden (Không Gánh Nặng Kỹ Thuật)
- **Standard:** The customer is a business executive, content creator, or agency operator — not a software engineer or cloud architect.
- **Enforcement:** All operations (workspace setup, BYOK key input, mission creation, team management, billing, and error diagnostics) execute entirely through the clean, bilingual web interface (`/dashboard`). The customer never touches a terminal, never writes SQL queries, and never logs into cloud infrastructure providers.

#### Principle 2: Self-Service Data Portability & Clean Exit (Rời Nền Tảng Tự Phục Vụ)
- **Standard:** Customer lock-in is unethical and commercially unacceptable. Customers own their data 100% and may exit at any time without penalty.
- **Enforcement:** In `/settings`, the customer can trigger a **1-Click ZIP Data Export** that packages all video assets, scripts, prompt templates, usage logs, and billing invoices into a portable archive. Workspace deletion triggers a 30-day soft pause followed by complete cascade purging of all assets and cryptographic destruction of stored API keys (`src/land/account/cascade-delete.ts`).

#### Principle 3: Zero Model Training & Cryptographic Secrecy (Không Huấn Luyện Mô Hình & Bảo Mật Tuyệt Đối)
- **Standard:** Customer video scripts, brand hooks, custom voices, and intellectual property are private property and must never be used to train public models.
- **Enforcement:** Sophia routes AI requests strictly through enterprise enterprise API tiers of upstream providers (OpenRouter, ElevenLabs, fal.ai, Replicate) under agreements that prohibit model training. All customer credentials are encrypted at rest with AES-256-GCM using unique initialization vectors (IVs) and authenticated user ID bindings. Secrets are write-only and permanently masked in the UI.

#### Principle 4: Strict Multi-Tenant Segregation (Phân Tách Dữ Liệu Tenant Tuyệt Đối)
- **Standard:** No customer organization may ever access, view, or affect another organization's data, missions, or compute quotas.
- **Enforcement:** Sophia employs double-layer IDOR protection:
  1. *Route Middleware Layer:* `verifyWorkspaceAccess` verifies Better Auth session membership against the target workspace before route execution.
  2. *Domain Repository Layer:* Every SQL query explicitly scopes by `workspace_id` or `user_id`. Attempting to access foreign assets returns HTTP 403 Forbidden.

#### Principle 5: Financial Sovereignty & Fail-Closed Invariants (Chủ Quyền Tài Chính Bền Vững)
- **Standard:** Every dollar or token paid must deliver exact, measurable compute units. Double billing and underpayment exploits are structurally impossible.
- **Enforcement:**
  - 1 Payment = 1 Fulfillment: Webhooks utilize database-level unique constraints (`INSERT INTO payment_events ... ON CONFLICT DO NOTHING`) to eliminate duplicate webhook replays.
  - PayOS IPN verifies expected VND amounts to block underpayment attacks.
  - Compute credits are deducted conditionally (`WHERE credits >= ?`) to guarantee balances never go negative.
  - Stuck or orphaned missions (> 15 min) are automatically reclaimed by the autonomous Mission Reaper with full credit compensation.

## 7. Disaster Recovery & Business Continuity / Quy Trình Dự Phòng & Khôi Phục Thảm Họa

Sophia AI Factory is engineered with automated, serverless disaster recovery capabilities ensuring high resilience against cloud regional failures or database corruption.

### 7.1 Recovery Objectives & Guarantees
- **Recovery Time Objective (RTO):** **≤ 15 minutes** (Export and execute restoration duration: ~90–180 seconds).
- **Recovery Point Objective (RPO):** **0 minutes at handover** (immediate manual snapshot) | **≤ 24 hours in routine operations** (automated daily cron backup).
- **Redundancy:** Automated SQLite database dumps stored across distributed Cloudflare R2 object storage independent of the D1 compute cluster.

### 7.3 Manual On-Demand Backup Commands

Execute an immediate production snapshot prior to any major schema change or milestone handover:

```bash
# 1. Create timestamped local backup directory
mkdir -p ./backups/handover

# 2. Export complete production D1 database to local SQL dump
npx wrangler d1 export sophia-raas-db \
  --remote \
  --skip-confirmation \
  --output ./backups/handover/d1-handover-live-$(date +%Y%m%d_%H%M%S).sql

# 3. Compute and store SHA-256 integrity checksum
shasum -a 256 ./backups/handover/d1-handover-live-*.sql > ./backups/handover/checksums.sha256

# 4. Verify dump completeness (must contain DDL and row inserts)
grep -q "CREATE TABLE" ./backups/handover/d1-handover-live-*.sql && echo "✅ DDL Schema: PASS" || echo "❌ DDL Schema: FAIL"
grep -q "INSERT INTO" ./backups/handover/d1-handover-live-*.sql && echo "✅ Data Inserts: PASS" || echo "❌ Data Inserts: FAIL"
ls -lh ./backups/handover/d1-handover-live-*.sql
```

### 7.4 Ephemeral Rapid Restore Drill Protocol (Zero-Risk Verification)

To independently prove that backups are restorable without touching production data:

```bash
# Step 1: Identify backup source file
BACKUP_FILE="./backups/handover/d1-handover-live-latest.sql"

# Step 2: Create an ephemeral isolated scratch database in Cloudflare D1
DRILL_DB="sophia-restore-drill-$(date +%y%m%d%H%M)"
npx wrangler d1 create "$DRILL_DB"

# Step 3: Execute full restoration against the ephemeral database
npx wrangler d1 execute "$DRILL_DB" --remote --yes --file="$BACKUP_FILE"

# Step 4: Verify row count parity against production
echo "=== Restored Ephemeral Database Counts ==="
npx wrangler d1 execute "$DRILL_DB" --remote --command "SELECT COUNT(*) AS total_tables FROM sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%' AND name NOT LIKE '_cf_%';"
npx wrangler d1 execute "$DRILL_DB" --remote --command "SELECT COUNT(*) AS users_count FROM user;"
npx wrangler d1 execute "$DRILL_DB" --remote --command "SELECT COUNT(*) AS missions_count FROM creative_missions;"

echo "=== Production Live Database Counts ==="
npx wrangler d1 execute sophia-raas-db --remote --command "SELECT COUNT(*) AS total_tables FROM sqlite_master WHERE type='table' AND name NOT LIKE 'sqlite_%' AND name NOT LIKE '_cf_%';"
npx wrangler d1 execute sophia-raas-db --remote --command "SELECT COUNT(*) AS users_count FROM user;"
npx wrangler d1 execute sophia-raas-db --remote --command "SELECT COUNT(*) AS missions_count FROM creative_missions;"

# Step 5: Decommission the ephemeral scratch database
npx wrangler d1 delete "$DRILL_DB" --yes
echo "✅ Drill complete: Restore verified, scratch database decommissioned."
```
