## Goal

Extract a single bilingual EN+VI HTML email component with a primary CTA button and EN/VI body slots. Existing per-flow templates become thin adapters that supply colors, headings, and copy. Eliminates duplicated HTML structure across 3 flows.

## Key Insights

1. **Common structure across all 3 templates:**
   - Outer `<body>` with same inline styles
   - `<h2>` + EN body
   - `<a>` button (color varies per flow: purple `#6750A4` change-email, red `#dc2626` delete)
   - `<hr>` separator
   - `<h3>` + VI body
   - Footer disclaimer
2. **What varies:**
   - Heading text (EN + VI)
   - Body paragraphs (EN + VI; sometimes 2 paragraphs each)
   - CTA color
   - CTA label (EN + VI)
   - CTA URL (one shared URL with raw token)
   - Footer disclaimer text (EN + VI)
3. **Where to put it:**
   - `src/seed/email/bilingual-cta-template.ts` — pure function, no domain knowledge → seed layer (foundational primitive).
   - Existing `src/forest/email/sender.ts` is where `sendEmail` lives. Template is sibling concept but at lower layer → seed.
4. **i18n integration:** Email content is already bilingual inline (not via next-intl). Keep that pattern. Component accepts pre-translated strings as props; consumers may import from `messages/{en,vi}.json` if desired.

## Implementation Steps

1. **Write `src/seed/email/bilingual-cta-template.ts`:**
   ```ts
   /**
    * Bilingual EN+VI HTML email with optional CTA button.
    * Wave 22 Phase 07 — DRY refactor across change-email + account-delete flows.
    */
   export interface BilingualEmailLocale {
     heading: string;
     paragraphs: string[];          // each rendered as <p>
     footer: string;                 // disclaimer line
     ctaLabel?: string;              // when CTA omitted, label ignored
   }

   export interface BilingualCtaEmailOpts {
     en: BilingualEmailLocale;
     vi: BilingualEmailLocale;
     cta?: { url: string; bgColor: string };
     accentColor: string;            // headings color
   }

   export function buildBilingualCtaEmail(opts: BilingualCtaEmailOpts): string {
     const { en, vi, cta, accentColor } = opts;
     if (cta && !cta.url.startsWith('https://') && !cta.url.startsWith('http://localhost')) {
       throw new Error(`[bilingual-cta-email] Invalid CTA URL: ${cta.url}`);
     }
     const safeUrl = cta ? cta.url.replace(/"/g, '&quot;').replace(/</g, '&lt;') : '';
     const ctaHtml = cta
       ? `<a href="${safeUrl}" style="display:inline-block;background:${cta.bgColor};color:white;padding:12px 32px;border-radius:8px;text-decoration:none;font-weight:600;margin:16px 0;">${escapeHtml(en.ctaLabel ?? 'Confirm')} · ${escapeHtml(vi.ctaLabel ?? 'Xác nhận')}</a>`
       : '';
     return `<!DOCTYPE html><html><head><meta charset="utf-8"></head>
<body style="font-family:-apple-system,sans-serif;line-height:1.6;max-width:600px;margin:0 auto;padding:24px;">
  <h2 style="color:${accentColor}">${escapeHtml(en.heading)}</h2>
  ${en.paragraphs.map(p => `<p>${escapeHtml(p)}</p>`).join('\n  ')}
  ${ctaHtml}
  <p style="font-size:13px;color:#666;">${escapeHtml(en.footer)}</p>
  <hr style="border:none;border-top:1px solid #eee;margin:20px 0;" />
  <h3 style="color:${accentColor};margin-bottom:8px;">${escapeHtml(vi.heading)}</h3>
  ${vi.paragraphs.map(p => `<p>${escapeHtml(p)}</p>`).join('\n  ')}
  <p style="font-size:13px;color:#666;">${escapeHtml(vi.footer)}</p>
</body></html>`;
   }

   function escapeHtml(s: string): string {
     return s.replace(/</g, '&lt;').replace(/&/g, '&amp;');
   }
   ```
   Keep ≤120 LOC. Inline escape to avoid extra util.

## Risk Assessment

- **R1: HTML diff regression** — Auto-tests check substrings, not exact bytes. Manual visual diff required to catch subtle layout shifts.
- **R2: Phase 06 rewrite double-work** — If P06 lands first with inline template, P07 rewrites it. Acceptable per dependency chain.
- **R3: Premature abstraction** — Three flows share the structure; this is sufficient justification per Rule of Three. Component does NOT try to handle all email shapes (e.g., transactional receipts) — explicit limited scope.

## Security Considerations

- Component is the SINGLE place URL validation occurs (Phase 03 logic embedded). Net: stronger defense in depth.
- `escapeHtml` applied to all user-supplied strings (heading, paragraphs, footer). Prevents accidental HTML/script injection if upstream caller forgets to escape.
