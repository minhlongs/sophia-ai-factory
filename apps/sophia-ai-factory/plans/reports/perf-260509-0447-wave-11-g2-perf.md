## F-PC-10: KV Writes Batching

**File modified:** `src/forest/usage-metering/usage-kv-sync.ts`

**Change:** Added `flushKvCounters()` that aggregates accepted records by `userId:service` key in-memory before flushing. `batchIngestUsage()` now:
1. Accumulates KV deltas in a `Map<string, KvCounterEntry>` during record loop
2. Calls `flushKvCounters(kvBuffer, waitUntil)` after D1 bulk insert succeeds
3. Clears buffer on D1 failure (prevents stale counter writes)
4. Defers KV flush via CF Workers `waitUntil` when provided (non-blocking)

**Write reduction estimate:**
- Before: 1 `kv.set` per accepted record → N KV writes per batch
- After: 1 `kv.set` per unique `(userId, service)` pair → M writes where M << N
- Typical workload (100 records, 4 user+service combos): **~96% reduction**
- Conservative estimate (mixed users, 10 combos per 50 records): **~80% reduction**

**API surface preserved:** `batchIngestUsage(records, userId)` still works; `waitUntil` is optional 3rd param.
