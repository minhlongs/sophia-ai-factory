## 4. Deploy-config drift (P1)

Root cause (proven): `wrangler.toml` uses `[[env]]` array-of-tables for `health`
and `ultracode`; wrangler reports available env names `["0","1"]`. The two
`wrangler secret put ... --env health || true` calls in deploy.yml Stage 3b and
the matching `if ! ... non-fatal` block in deploy-with-sha.sh therefore always
failed and were hidden. Three top-level secret puts (COMMIT_SHA/DEPLOYED_AT/
DEPLOY_BRANCH) are the real `/api/version` metadata contract and already fail
loud.

`/api/health` is a self-contained App Router route on the MAIN worker (changelog:
"proxied to dead external worker … Replaced with self-contained local health
check"). The standalone `sophia-ai-factory-health` worker (wrangler.health.toml)
is NOT deployed by deploy.yml and has no consumer in this pipeline. Hence the
health-env propagation is dead config; no functionality is lost by removing it.

Change: remove dead calls in BOTH files, document root cause, keep 3 fail-loud
secret puts. Add `scripts/__tests__/deploy-env-consistency.test.ts` which reads
the real deploy.yml/fallback script/wrangler.toml and fails on: any `--env NAME`
not addressable, any `\|\| true` on a critical secret put, any residual
`--env health`, and any silent change to the `[[env]]` shape. Proven RED (3
assertions) when a dead call is reintroduced.

`wrangler.toml` NOT changed (BLOCKER, architectural): converting `[[env]]` to
real `[env.health]`/`[env.ultracode]` named tables would change worker naming,
binding inheritance and deploy topology for the main production Worker. That
needs (a) a founder/CTO decision on whether the standalone health worker is
still needed, and (b) Cloudflare credentials + a non-prod deploy to verify.
Options: (A) keep as-is + keep the guard (current, minimal); (B) delete the
dead `[[env]]` blocks entirely (health-worker.ts + wrangler.health.toml become
orphans — decide first); (C) convert to real named envs and re-introduce
verified propagation. Not done without authority.
