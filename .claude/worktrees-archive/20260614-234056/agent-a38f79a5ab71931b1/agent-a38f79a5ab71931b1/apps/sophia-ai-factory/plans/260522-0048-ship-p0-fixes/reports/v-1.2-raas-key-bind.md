# V-1.2 RaaS API Key User-Binding Fix

**Date:** 2026-05-22
**CVSS:** 9.6 (was: valid key holder could impersonate any userId in body)
**Status:** FIXED

---

## Root Cause

`validateRaasApiKey` returned `boolean` only — the route trusted `body.userId` directly, allowing any valid-key holder to create campaigns as any user.

## Changes Made

### 1. `src/app/api/v1/campaigns/create/route.ts`

- Added `RaasApiKeyValidationResult` interface: `{ valid, userId: string|null, orgId? }`
- `validateRaasApiKey` now selects `user_id` from `raas_licenses` and returns it
- `createCampaignBodySchema.userId` changed from `required` → `optional`
- Route handler: derives authoritative `userId = keyResult.userId` from validated key
- Added impersonation guard: if `body.userId` present and differs from key owner → 403
- Added unbound key guard: if key valid but `user_id` is null → 403
- Changed invalid-key response from 403 → 401 (authentication failure, not authorization)

### 2. `src/app/api/v1/campaigns/create/__tests__/route.security.test.ts` (NEW)

6 security tests:
- (a) valid key, no body.userId → 201, campaign created under key owner
- (b) valid key, body.userId = different user → 403
- (c) invalid/unknown key → 401
- (d) valid key, body.userId matches key owner → 201 (no false positive)
- (e) revoked key (is_revoked=1) → 401
- (f) valid key, user_id=null in license record → 403

### 3. `src/app/api/v1/campaigns/create/__tests__/route.contract.test.ts` (updated)

Updated 2 tests and added 1 to reflect `userId` now optional in body schema.
