## 2. Logic Chain

1. **PayOS Description Mismatch & Webhook Breakdown**:
   - Because production checkouts strip the user ID prefix to fit PayOS character limits, we cannot parse the `userId` directly from description.
   - We updated `route.ts` in both the success and cancellation paths to directly query the `pending_orders` table filtering by `payment_method = 'payos'` and `status = 'pending'`.
   - Once orders are fetched, we find the one whose `invoice_url` contains `paymentLinkId` or `orderCode` of the IPN payload.
   - We then resolve `userId` from `matchOrder.user_id`, `tier` from `matchOrder.tier`, and `orderId` from `matchOrder.order_id`, bypassing the description parsing completely.

2. **Robustness on Lock Conflicts (Concurrent Requests)**:
   - If two concurrent requests try to insert, the second request fails insertion.
   - We updated the conflict block to query the event status. If `processed` is `0` (or `false`), it indicates it is still processing.
   - Instead of returning a success code, we now return a failure status: status `409` with error message `'Already processing'` (in PayOS `route.ts`) and `{ success: false, message: 'Already processing' }` (in NowPayments `nowpayments-ipn-handlers.ts`).
   - This ensures the webhook provider sees a failure and correctly schedules a retry instead of dropping the webhook.

3. **Robustness on Database Query Failures**:
   - In both files, if `insertError` occurs and the subsequent SELECT query fails (either due to a `selectError` or returning null/undefined data), we return a failure: status `500` with message `'Database query failure'` (in PayOS `route.ts`) and `{ success: false, message: 'Database query failure' }` (in NowPayments `nowpayments-ipn-handlers.ts`).
   - This prevents silent success responses during database connection drops, ensuring subsequent retries when the database is restored.

## 3. Caveats

- We assumed that the list of pending orders matching `payment_method = 'payos'` and `status = 'pending'` is small enough to be loaded in memory for mapping. Since orders expire or get processed, this list remains small.
- We did not perform live testing against the PayOS production API endpoints but verified against simulated test suites.
